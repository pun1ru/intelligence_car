# 嵌入式 C 代码规范

适用范围：本仓库新增和修改的自有代码，即 `project/user`、`libraries/myAlgorithm`、`libraries/myApplication`、`libraries/myDriver`。逐飞库、NXP SDK、FreeRTOS 和其他第三方代码保留原有风格；修改第三方代码时尽量使用适配层，避免直接改动供应商源码。

## 1. 基本约定

- 使用项目当前工具链支持的 C 语法，优先采用 C99 常用特性；不要依赖编译器扩展，确实需要时在使用处说明原因。新增代码保存为 UTF-8，统一使用 4 个空格缩进，不混用制表符。
- 一行只做一件事。控制语句始终使用花括号，花括号独占一行；`switch` 的每个 `case` 明确结束方式，故意贯穿时写注释。
- 函数保持单一职责。出现较长的初始化流程、嵌套判断或重复逻辑时，拆成有明确输入输出的 `static` 函数。避免用宏代替普通函数。
- 不允许依赖隐式函数声明、隐式类型转换来掩盖告警。新增代码应在现有编译配置下无新增告警；关闭告警必须写明原因和范围。

## 2. 命名与文件

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 文件、函数、变量 | 小写 `snake_case`，名称表达用途 | `motor_set_duty()`、`sample_period_ms` |
| 自有模块对外符号 | 带模块前缀，避免全局命名冲突 | `motor_driver_init()`、`vehicle_control_step()` |
| 类型 | 小写 `snake_case` 加 `_t`；避免与 SDK 类型重名 | `motor_command_t` |
| 宏、枚举常量 | 大写 `SNAKE_CASE`，带所属模块前缀 | `MOTOR_MAX_DUTY` |
| 文件内对象 | 默认 `static`，无须跨文件暴露 | `static uint32_t last_count;` |

- 新增自有文件放在对应层目录。Application 和 Driver 新文件分别建议采用 `app_*.c/.h`、`drv_*.c/.h`；Algorithm 延续 `pid/pid.c` 等按算法命名的现有方式。`user` 中任务文件采用 `*_task.c/.h`。目录和文件名共同标明层次，不把跨层代码放入通用 `utils` 文件。
- 头文件名与实现文件名配对。新文件避免拼写错误及同义名并存；历史文件不因应用本规范而强制批量改名。
- 公共头文件只暴露调用者需要的类型、常量和函数。实现细节、可变状态及仅本文件使用的声明留在 `.c` 中。头文件可单独被包含，且使用不以双下划线或下划线加大写字母开头的 include guard，例如 `APP_VEHICLE_CONTROL_H`。
- `.c` 文件先包含对应的 `.h`，再包含标准库、依赖模块头文件。避免通过 `general_include.h` 一类汇总头间接获得声明；依赖谁就显式包含谁。

## 3. 类型、数值与接口

- 对协议、寄存器、采样数据和有确定宽度要求的值使用 `<stdint.h>` 中的 `uint8_t`、`int32_t` 等类型。长度和数组下标使用 `size_t`；与逐飞接口交互时只在边界处转换其 `uint8` 等类型，并检查范围。
- 数值常量写明单位和含义。变量、参数或结构体字段用 `_ms`、`_hz`、`_rad_s` 等后缀标识单位；无量纲值也要在接口文档中说明范围。浮点常量需要 `float` 精度时加 `f` 后缀。
- 带符号和无符号数混算、窄化转换、数组长度计算、定时计数回绕都应显式处理。缓冲区接口同时传入容量；写入前检查边界，检查加法、乘法是否可能溢出。
- 输入参数尽量使用 `const`；只读数组和结构体优先传 `const` 指针。输出通过返回值或输出参数表达，不用可写全局变量作为隐藏返回值。每个接口说明输入范围、失败返回、输出是否在失败时有效。
- 可恢复错误用模块定义的状态值或明确的返回码，并由调用方处理。对不可恢复的内部不变量，可使用断言或安全停机策略，但不得把普通运行错误只交给断言。
- `volatile` 仅用于硬件寄存器或确实会被 ISR/其他执行上下文异步改变的对象；它不保证读写原子性，也不能代替临界区、互斥量或消息机制。

## 4. 状态、内存与并发

- 明确模块状态归属：算法状态由调用者持有或由模块封装；跨任务数据优先通过队列、通知或受保护的快照传递，不暴露可写全局结构体。
- 优先静态分配或由调用者提供工作缓冲区。需要动态分配时限定在初始化阶段，检查失败并明确释放时机；周期控制路径和 ISR 中不做动态分配。
- 任务周期内避免无上限循环、长时间阻塞和不受控打印。关键路径说明最坏执行时间或超时策略；共享外设访问要约定所有权。
- ISR 只采集必要状态、清中断和通知任务；只调用可在 ISR 使用的接口。ISR 与任务共享多字段数据时使用快照、双缓冲或临界区，避免读到不一致状态。
- GPIO、PWM 等上电默认状态和异常状态应安全明确；执行器输出在应用/驱动边界做范围限制，错误路径给出安全输出。

## 5. 注释与验证

- 注释解释约束、单位、时序、硬件原因和非显然的算法假设，不重复代码字面含义。公共接口注释至少说明用途、参数单位/范围、返回值及调用上下文限制。
- 新增或修改算法时，覆盖正常输入、边界值、异常输入及状态重置；能脱离硬件运行的算法优先做主机侧单元测试。驱动和任务改动至少完成编译，并在板上核对初始化、周期、超时及异常安全状态。
- 提交前核对：新增文件进入 Keil 工程及 include path；无新增编译告警；没有跨层反向依赖；第三方目录没有无关改动。

## 6. 接口示例

```c
#ifndef APP_VEHICLE_CONTROL_H
#define APP_VEHICLE_CONTROL_H

#include <stdint.h>

typedef struct
{
    float target_speed_m_s;
    float measured_speed_m_s;
} vehicle_control_input_t;

typedef struct
{
    int16_t motor_duty_permille; /* 范围：-1000 到 1000 */
} vehicle_control_output_t;

/* 每个控制周期调用一次；参数不得为 NULL。 */
void vehicle_control_step(const vehicle_control_input_t *input,
                          vehicle_control_output_t *output);

#endif
```

此示例展示命名、单位和输入输出约定，不规定项目必须采用这一具体接口或数据类型。
