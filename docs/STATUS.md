## 任务与约束

- 东南大学智能车校赛 · 惯导组。场地**无标线、只有锥桶**，不等间距排成一列。
- 从起跑线前 1 m 内出发，依次穿过锥桶间隙，返回发车线，**不要求停车**。
- 传感器只允许 **IMU + 编码器**（禁 GPS/RTK/UWB）。**正式发车禁用无线**，上位机只能调试用。
- 锥桶排布**比赛前一日公布** → 路径必须能改（本项目用编译期路径表，改表重烧）。
- 罚则：遗漏穿桶 +30s，撞倒/明显位移 +3s，轻触 +1s，停止 >10s 成绩无效。

## 硬件

RT1064 核心板 + 主板；IMU660RC（SPI4）；双编码器（QTMR1，1024 线×68/30 = 2321 计数/轮圈）；双直流电机（PWM+DIR）；无线串口 UART8（TX=D16 / RX=D17）；TFT180 屏；模式拨码 C26/C27；按键 C12–C15。

## 软件结构

7 个 FreeRTOS 任务：`state / estimate / control / receive / send / debug / decision`。
分层：`task → myApplication → myAlgorithm → myDriver`。

| 任务 | 干什么 |
| --- | --- |
| `estimate_task` | Madgwick 姿态、零偏校准 |
| `receive_task` | 传感器快照（IMU / 编码器 / 姿态队列） |
| `state_task` | 按键、拨码、串口命令 → 车辆状态机 |
| `control_task` | 每 5 ms 调 `app_control_step`：三环 PID + 路径跟踪接管 |
| `decision_task` | 位姿积分 + 领航员（`app_nav`），每 10 ms |
| `send_task` | 三种上行帧，错开时隙发送 |
| `debug_task` | 屏幕（最后一行显示位姿 X/Y） |

## 已完成并验证

1. **姿态**：Madgwick 可用。**关键：零偏必须"热机几分钟后再校准"**——否则 0.78°/s 漂移；热机校准后 **0.003°/s**（2 分钟只漂 0.3°）。校准结果只在 RAM，**每次断电都要重做**。
2. **位姿**：编码器里程 + yaw 积分 → `x / y / 朝向`。实测推 92 cm 读数 0.92（误差 0.1%）；原地转 90° 平移≈0。原点在进入导航时重设。
3. **路径跟踪**：`pure_pursuit`（29 项主机测试）+ 路径表 + `app_nav`（坐标换算 + 三态门控），**已接入控制环**：导航状态下由跟踪指令替换手动目标并强制开转向环，其余情况回退到状态机（导航下为 0，即原地平衡）。
4. **台架验证通过**：手推 92 cm，实测 `x=0.91 / yaw=−17.6° / cross=+0.07 / pt=1`，与手算期望最大差 0.6° → 整条链正确。
5. **无线与上位机**：静置 7 分钟 `lost 0 / bad 0`；轨迹页显示 `Nav: off / ready / driving`。

## 关键参数与开关（都在 `general_define.h`）

| 名称 | 当前值 | 说明 |
| --- | --- | --- |
| `NAV_TRACKING_ENABLE_DEFAULT` | 1 | 跟踪总开关（比赛禁用无线，必须在这里定好） |
| `NAV_TRACKING_DRIVE_ENABLE` | 1 | 1=驱动电机；**0=只算不动**（台架验证用，车不会动） |
| `NAV_TRACKING_LOOKAHEAD_M` | 0.40 | 前视距离，调大走线更平缓 |
| `NAV_TRACKING_SPEED_MAX/MIN_M_S` | 0.20 / 0.15 | 功能验证阶段的保守值，确认能跟线后再逐步加 |
| 角度环 / 速度环 / 转向环 | 600/0/30、24/3/0、30/2/0 | 均已写回源码，断电不丢 |
