## 1. 任务与硬约束（设计都是被这些约束逼出来的）

- 场地**无标线、只有锥桶**，不等间距排成一列；从起跑线前 1 m 内出发，依次穿过锥桶间隙，返回发车线，**不要求停车**。
- 传感器**只允许 IMU + 编码器**（禁 GPS/RTK/UWB）→ 所以用"编码器里程 + yaw 积分"做位姿，没有绝对位置。
- **正式记录成绩的发车禁用无线** → 路径/参数必须编译进固件；上位机只能调试用。
- 锥桶排布**比赛前一日公布** → 路径表要能快速替换（现在就是"改表 + 重烧"）。
- 罚则：遗漏穿桶 +30s、撞倒/明显位移 +3s、轻触 +1s、停止 >10s 成绩无效
  → **宁可绕大一点也不撞**；速度要留余量。

## 2. 软件结构（谁在哪）

7 个 FreeRTOS 任务（`project/user/src/`）：`state`（按键/拨码/串口→状态机）、
`estimate`（Madgwick 姿态 + 零偏校准）、`control`（5 ms 调 `app_control_step`）、
`receive`（传感器快照）、`send`（三种上行帧）、`debug`（屏幕）、**`decision`（位姿 + 领航员，10 ms）**。

## 3. 导航层思路（核心）

```
编码器计数 ─差分成轮行程─┐
                        ├─▶ odometry ─▶ 位姿(x, y, 朝向)
IMU yaw ────────────────┘                      │
                                               ▼
路径表(点列) ─────────▶ app_nav ─▶ pure_pursuit ─▶ 目标速度 + 目标航向(IMU 坐标系)
                                     │
                                     └─▶ 0x82 帧 ─▶ 上位机显示 Nav: off/ready/driving
                                     └─▶ app_control ─▶ 三环 PID ─▶ 电机
```

四个关键设计决定：

1. **坐标系**：发车点为原点、**车头方向为 0°**、`+X` 向前、`+Y` 向左、航向逆时针为正。
   进入导航状态那一刻重新定原点 → **起跑线就是 (0,0)**，不需要绝对航向。
2. **航向换算**：`pure_pursuit` 算出的期望航向在"路径坐标系"里，必须**加上定原点时的 IMU yaw 偏移**才能给转向环（转向环比的是 IMU 绝对 yaw）。这一步在 `app_nav_step()` 里做。
3. **三道门控**：只有在"跟踪已使能 + 位姿可信 + 路径表非空"时才输出有效指令（`active=1`）；否则指令清 0，控制环回退到状态机目标（导航状态下为 0 → 原地平衡）。**宁可不动，也不用错指令。**
4. **算指令与驱动解耦**：指令在**任何状态**都算（保护状态手推车也能看到），只有"导航状态 + `NAV_TRACKING_DRIVE_ENABLE=1`"才真的驱动电机。这样台架验证零风险。

**Pure Pursuit 的工作方式**：找路径上离车最近的点 → 从那里**沿路径往前量"前视距离"**得到前视点 → 车朝它走；速度按估出的曲率在上限/下限之间缩放。

三个后加的工程细节（2026-10-19，都是 0.40 m/s 实车暴露出来的）：

1. **前视距离随速度**：`L = 0.55 s × 上一拍目标速度`，限幅 `[0.15, 0.30] m`。0.40 m/s 时 0.22 m，弯里（0.32 m/s）0.18 m。**不要再用 0.9 s**：0.40 m/s 会给 0.36 m，接近转弯半径 0.4 m，纯跟踪几何上会让车整段贴在弯道内侧（实车内切约 10 cm）。固定前视距离在高速下还会一个点一个点地追，折线问题现在由"前视点段内插值"解决。
2. **终点减速曲线**：`v ≤ 1.0 × 剩余距离`（`NAV_TRACKING_END_STOP_GAIN_PER_S`）。0.60 m/s 时从 0.6 m 外开始收油，剩 0.1 m 时只剩 0.1 m/s。**不要改回 sqrt 曲线**：sqrt 在最后 10 cm 还允许 0.35 m/s，0.60 m/s 实车会冲过终点。
3. **终点锁存**：一旦进入终点半径**或**沿末段方向冲过终点 3 cm，就永久锁存 `finished`，直到 `app_nav_reset()`（换路径/Reset pose）。否则冲过终点后离最后一点变远、判定变回"没到"，车会掉头回去追，表现为冲过终点后原地打转。

另外目标速度每拍最多变化 `0.6 m/s² × dt`，避免分段曲率算出来的速度目标一跳一跳地激起车身前后晃。

| 参数（`general_define.h`） | 当前值 | 管什么 |
| --- | --- | --- |
| `NAV_TRACKING_ENABLE_DEFAULT` | 1 | 跟踪总开关（比赛禁用无线，必须在这里定） |
| `NAV_TRACKING_DRIVE_ENABLE` | 1 | 1=驱动电机；0=只算不动（台架验证用） |
| `NAV_TRACKING_LOOKAHEAD_M` | **0.18** | 前视距离=车"看多远"。大→平缓但**抄内圈**；小→贴线但**易抖**。**硬约束：≥2× 路径点间距** |
| `NAV_TRACKING_SPEED_MAX/MIN_M_S` | **0.20 / 0.15** | 目标速度上下限（现在为了看清行为压得很低） |
| `NAV_TRACKING_SLOW_RADIUS_M` | 0.50 | 曲率半径小于它开始减速 |
| `NAV_TRACKING_GOAL_RADIUS_M` | 0.10 | 离最后一个点多近算"到点"→ 目标速度归零刹车 |

## 5. 当前存在的问题（都有数据支撑）

1. **转弯时车偏在弧的内侧约 5 cm**（`cross` 最小 −0.05）。
   原因：Pure Pursuit 固有特性 + 前视距离仍偏大（进弯瞬态抄角）。
   候选改法：**弧继续加密 + 前视再小一点（两者必须配套，前视 ≥ 2× 点距）**。
2. **出弯后外摆到 +0.12 m**，然后被直线上慢慢拉回到 +0.05。
   原因待定，两种可能：① **转向环跟不上**（PID 输出限幅 `BALANCE_STEERING_PWM_LIMIT = 1000` 可能饱和——历史上就发现过大角度饱和问题）；② 进弯瞬态的欠阻尼过冲。
   **另外**：从 −0.05 直接跳到 +0.12（17 cm）在 0.2 m/s 下物理上不可能，说明**至少有一部分是测量跳变**——`cross` 用"最近一段路径的垂距"算，跨过拐点时参考段会切换，读数会跳。这是"最近段法"的固有特性。
   **判定方法（下一步就该做）**：跑一次，同时记 ① 转弯中"目标 yaw − 实际 Yaw"的最大值（大 → 限幅/增益；小 → 瞬态/位姿）；② 轨迹页拍照看形状（S 形过冲 or 单点跳变）。
3. **终点判定半径 0.10 m 会"提前刹车"**：落点散布 3~5 cm；停在弧上时少转 0.10/0.40 rad ≈ 14°。
   已用"**弧后加一段直线**"缓解（直线上早停晚停都不改变朝向要求）——实车已验证：**最后朝向正确**。
4. **位姿在转弯中的精度未知**（可能打滑）。验证方法：把车端橙色轨迹与地面画的弧对比，或跑的时候读 `Vehicle pose` 与地面位置对照。
5. **转向环不是为跟踪调过的**：`Kp=30 / Ki=2 / FF=10 PWM/deg` 是按"手动给 yaw 目标"调的，跟路径时的稳态滞后没专门调。
6. **速度还压在 0.20 m/s**（功能验证阶段刻意压低）。确认跟踪可靠后要逐级加（0.20→0.30→0.40…），每级确认能站住。
7. **路径表是测试路径**，比赛坐标要等前一日公布；另外**起跑/返回发车线的逻辑尚未实现**（现在终点即停，而规则"不要求停车"）。
8. **零偏断电即丢**：每次上电都要重新校准（20 秒静置）。
9. **调试帧率受限**：无线模块吞吐约 700 B/s，所以位姿/校准帧只能 2 Hz、遥测 100 ms；不要随意加回 10 Hz。

## 7. 坑与注意事项（都是踩过的）

- **烧录**：关车总电源、拔屏幕；**烧完必须拔 DAP**（插着跑程序内核会被停住 → 屏幕白屏 + 按键无反应，看着像死机，其实不是）。
- **Keil 里改完必须保存**（Ctrl+S）再下载，否则烧的是旧文件（已踩过一次）。
- **上电顺序固定**：上电 → 热机几分钟 → 20 秒静置校准（C26/C27 双开 + 按一下 C12，或上位机 `Calibrate gyro bias (20 s still)`）→ 发车。
- **无线**：三种上行帧不能连发（模块吞吐不足会丢帧）；上位机**画图必须限流**（限到 5 Hz，否则拖慢串口读取导致"超时"）。
- **导航状态下别把车拿起来**：位姿会乱，它会追着乱目标原地打转。要动它先按 Protect（C15）。
- **Protect = 直接断电**，平衡车会倒；跟路线时"Stop motion"按钮无效（被跟踪指令覆盖）。
- 上位机版本标记在窗口标题（现在 `[v10-pose]`）；改过 `main.py` 后**必须关掉重开**才生效。

## 8. 上位机读数怎么读

轨迹页顶部一行：`Nav: driving  v=0.18 m/s  yaw=-6.3 deg  cross=+0.03 m  pt=1`

| 字段 | 含义 |
| --- | --- |
| 状态 | `off` 无有效指令 / `ready` 算出来了但没驱动 / `driving` 正在按它控制 |
| `v` | 目标速度 |
| `yaw` | 目标航向（IMU 坐标系，可直接和车体状态栏的 `Yaw` 比较，两者之差就是转角误差） |
| `cross` | 横向偏差，**正=车在路径左侧**，负=右侧 |
| `pt` | 正在追第几个路径点 |

另外 `Vehicle pose (x, y)` / `Vehicle path length` 在窗口顶部 `Vehicle state` 框；车上 TFT 最后一行也显示 `X:`/`Y:`（不依赖无线，台架标定用）。

轨迹页顶部还有两个按钮，别混：

| 按钮 | 作用 |
| --- | --- |
| `Reset trajectory` | 只清上位机屏幕上的旧轨迹线，车端位姿**不动** |
| `Reset pose (origin here)` | 发命令给车端：把此刻位置记为 (0,0)、车头记为 0°、路径跟踪从第 1 个点重来；同时车端切回保护状态并清屏。陀螺零偏不受影响，所以推车重测不用断电重校准 |

轨迹图上三条线：**灰色虚线 = 参考路径**（上位机直接解析 `app_nav_path.c` 的
`nav_path_points[]`，不另抄一份），**蓝色 = 上位机用遥测轮速+yaw 自己积分**
（纯诊断，不参与控制），**橙色 = 车端位姿**。蓝橙应该贴合灰色虚线；橙线的折线
如果明显，先确认是不是位姿帧采样太粗（当前 5 Hz，0.4 m/s 下约 8 cm 一点）。
蓝线出现**断口**表示那段时间遥测丢了（丢帧/缺轮速或姿态/lift 标志），
上位机会把线断开而不是连一条假直线；此时去看 `lost/bad`。

- **四轮阿克曼、舵机转向**、CAN 驱动电机、手柄遥控；
- BNO08x 智能 IMU（400 Hz 游戏旋转矢量，六轴无磁力计，和我们一样没有绝对航向）；
- 导航方式是**示教—回放**：每走 1 cm 记录一次累计 yaw，存进 flash；回放时按里程查表得到目标 yaw，用 yaw PID 驱动舵机；前视格数随速度变化；根据"前方 yaw 变化"提前加减速。

对比结论：

| 维度 | 对方 | 我们 |
| --- | --- | --- |
| 横向纠偏 | **没有**（开环回放） | 有（Pure Pursuit 闭环纠偏） |
| 抗位姿漂移 | 强（不用 x/y） | 弱（依赖位姿） |
| 生成路径成本 | 低（开一遍就录好） | 高（要量锥桶坐标） |
| 可维护性 / 可视化 | 弱（单文件 1546 行、调试靠串口） | 强（分层 + 主机测试 + 上位机） |

**已采纳 / 暂缓（2026-10-19 决定）**：

- ✅ **前视距离随速度变化（方案已定，尚未实现）**：改为 `L = 0.9 s × 当前目标速度`，限幅 `[0.15, 0.50] m`。注意 0.9 × 0.20 = 0.18 m，**正好等于当前值**，所以实现后对这一趟没有行为变化，只是为提速做准备。
- ❌ **示教录路径**：不做。理由：绕锥桶没有固定赛道范围，不需要绝对精准；手工量坐标够用。
- ⏸ **转向加阻尼（D 项/陀螺角速度项）**：暂缓。它仍是"出弯外摆 0.12 m"的首要嫌疑，但**先测"目标 yaw − 实际 Yaw"的转角误差**再决定，不盲调。
- ⚠️ **输出速率限幅（可参考，待评估）**：只建议加在速度目标上，**不要加在转向输出上**——我们当前的问题是转向"跟不上"，给转向加限幅只会更慢。另外对方的"积分分离/抗饱和"我们 `control_pid.c` 已有（积分限幅 + 饱和时停止积分 + 微分滤波），不需要照抄。
